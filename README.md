# shiru

A TypeScript monorepo created with [Better-T-Stack](https://github.com/AmanVarshney01/create-better-t-stack): React, TanStack Router, Hono, oRPC, Drizzle, Better Auth with Polar, and shadcn/ui. Both apps run on Cloudflare Workers. [Vite+](https://viteplus.dev) handles installing, running tasks, linting, formatting, and type checking.

## Getting started

```bash
vp install
```

Create `apps/api/.env`:

```dotenv
DATABASE_URL=postgres://...
BETTER_AUTH_SECRET=<at least 32 characters>
POLAR_ACCESS_TOKEN=...
```

Create `apps/dashboard/.env`:

```dotenv
VITE_API_URL=http://localhost:3000
```

Push the schema and start both apps:

```bash
vp run db:push
vp run dev
```

The dashboard runs at http://localhost:3001 and the API at http://localhost:3000.

## Environment

The API reads bindings from `cloudflare:workers`. `apps/api/cloudflare.config.ts` declares them, and `cf dev` and `cf build` generate their types into `.cloudflare/types`.

- `DATABASE_URL`, `BETTER_AUTH_SECRET`, and `POLAR_ACCESS_TOKEN` are Worker secrets. Locally, they come from `apps/api/.env`.
- `CORS_ORIGIN`, `BETTER_AUTH_URL`, and `POLAR_SUCCESS_URL` are plain text bindings. They default to localhost in development. Production builds read them from `apps/api/.env.production` or the process environment.
- The dashboard reads `VITE_API_URL` from `apps/dashboard/.env` in development and `apps/dashboard/.env.production` in production builds. It is baked into the bundle, so rebuild when it changes.
- Drizzle commands read `DATABASE_URL` from `apps/api/.env`.
- PostHog is off in development and whenever no key is set. For production, set `POSTHOG_KEY` (and optionally `POSTHOG_HOST`) in `apps/api/.env.production` to report API errors. Set `VITE_POSTHOG_KEY` (and optionally `VITE_POSTHOG_HOST`) in `apps/dashboard/.env.production` for dashboard analytics.

## Deployment

Authenticate once with `cf auth login` from `apps/api`.

Create `apps/api/.env.production` with your public URLs:

```dotenv
CORS_ORIGIN=https://app.example.com
BETTER_AUTH_URL=https://api.example.com
POLAR_SUCCESS_URL=https://app.example.com/success?checkout_id={CHECKOUT_ID}
```

Create `apps/dashboard/.env.production` with `VITE_API_URL` set to the deployed API origin.

On the first deploy, upload the three secrets from a separate ignored file:

```bash
cd apps/api
cf deploy --secrets-file .env.secrets.local
```

After that, `vp run deploy:api` and `vp run deploy:dashboard` keep the uploaded secrets.

## UI

Shared shadcn/ui primitives live in `packages/ui`. Design tokens are in `packages/ui/src/styles/globals.css`.

```bash
npx shadcn@latest add dialog popover -c packages/ui
```

```tsx
import { Button } from "@shiru/ui/components/button";
```

Run the shadcn CLI from `apps/dashboard` for app-specific blocks.

## Scripts

- `vp run dev`, `vp run dev:dashboard`, and `vp run dev:api` start the dev servers.
- `vp run build` builds both apps.
- `vp check` formats, lints, and type checks. `vp check --fix` applies fixes. Route and binding types are generated by dev or build, so run one of them first on a fresh clone.
- `vp run check-types` type checks only.
- `vp run deploy:dry-run` validates the build output without uploading.
- `vp run db:push`, `db:generate`, `db:migrate`, and `db:studio` run Drizzle Kit.
- `vp run hooks:setup` installs the Vite+ Git hooks. The `staged` block in `vite.config.ts` sets what runs on commit.

CI (`.github/workflows/ci.yml`) installs, builds, runs `vp check`, and does deploy dry runs. It uses example URLs and needs no secrets.

## Structure

```
apps/
  dashboard/          React + TanStack Router frontend
  api/                Hono + oRPC API on Workers
    drizzle/          generated migrations
    src/routers/      oRPC routers
    src/schema/       Drizzle tables
    src/utils/        db, auth, context, and oRPC procedures
packages/
  ui/                 shadcn/ui components and styles
```

The dashboard imports the router type straight from `apps/api/src/routers`, so API changes type check end to end.
